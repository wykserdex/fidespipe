# fidespipebot — платные досье в Telegram

Продукт поверх движка: человек пишет боту `@ник` или адрес, получает бесплатный
быстрый скан, за полный отчёт платит 3 USDT через Crypto Bot и получает три файла,
которые можно сверить друг с другом.

```
/check @wykserdex      → бесплатно: 6 профилей из 19 сайтов, счётчики без ссылок
/buy a1b2c3d4          → инвойс Crypto Bot на 3.00 USDT (30 минут на оплату)
(оплата)               → движок гоняет username_full; в чат летят
                         report.html · evidence.json · journal.jsonl
```

Платная часть — это не «ещё немного данных», а другой объём: измерено на
реальном прогоне, бесплатный скан даёт 6 находок с 19 сайтов, платный — 13
находок с 420 сайтов (sherlock по всей базе + maigret по своей).

## Что нужно поставить

1. **Токен бота.** @BotFather → `/newbot` → скопировать токен.
2. **Токен платежей.** @CryptoBot → Crypto Pay → Create App → скопировать API-токен.
   Никакого эквайринга и верификации по 18+: оплата приходит USDT на кошелёк.
3. **Доноры плагинов** в тот же Python, который увидит бот:
   ```
   pip install sherlock-project==0.16.2 holehe==1.61 maigret==0.6.6 dnspython==2.8.0
   ```
4. **Бинарники** движка и бота:
   ```
   go build -o fidespipe.exe ./cmd/fidespipe
   go build -o fidespipebot.exe ./cmd/fidespipebot
   ```

## Конфиг

Скопировать `product/bot.config.example.json` → `product/bot.config.json`
(файл в `.gitignore`, токены в репозиторий не попадают) и вписать:

| поле | что значит |
|---|---|
| `telegram_token` | токен из BotFather. Без него бот не стартует |
| `cryptobot_token` | API-токен Crypto Pay. Пустой — бот живёт, но на `/buy` честно говорит, что платежи не настроены |
| `admin_tg_id` | твой numeric chat id: туда падают уведомления об оплатах и о сбоях |
| `fidespipe_bin` | путь к `fidespipe(.exe)`; относительный — от `repo_root` |
| `repo_root` | каталог репозитория (от него видны `product/pipelines` и `plugins/`) |
| `python_bin` | интерпретатор, в который ставили доноров. Нужен, чтобы найти каталог `Scripts` |
| `price_usdt` | цена досье, по умолчанию `3.00` |
| `free_cooldown_seconds` | как часто одному человеку можно бесплатный скан (по умолчанию 600), чтобы бот не превращался в бесплатный публичный сканер |
| `max_concurrent_runs` | сколько прогонов одновременно |

### Зачем тут `python_bin`

Ядро передаёт плагинам `PATH` и узкий список системных переменных, а
произвольные переменные не пропускает — иначе окружение пользователя протекало
бы во внешний код. Поэтому `HOLEHE_BIN` плагину не виден, и единственный
легальный способ познакомить плагин с `holehe.exe` — `PATH`. На Windows pip
кладёт этот исполняемый файл в `Scripts` рядом с интерпретатором, которого в
`PATH` обычно нет. Бот сам спрашивает у `python_bin`, где этот каталог, и
подставляет его в `PATH` дочернего процесса.

Проверено тестом, который прогоняет `email_full` дважды: без каталога в `PATH`
шаг holehe не отрабатывает, с ним — 122 сайта.

```
FIDESPIPE_BOT_E2E=1 go test ./internal/bot -run Donor -timeout 20m
```

## Запуск

```
./fidespipebot.exe -config product/bot.config.json
```

Long polling, поэтому хостинг, домен и HTTPS не нужны — бот работает из-за NAT,
можно держать запущенным на своей машине или на VPS за 3 €.

Остановить — Ctrl+C. Заказ, оставшийся в состоянии `awaiting_payment`, бот
подбирает после перезапуска (состояние в `var/bot/orders.jsonl`).

## Выдать отчёт вручную

Если оплата прошла, а в чат что-то не долетело (или клиент попросит
переслать), отчёт пересобирается из уже существующего прогона — движок
заново не гоняется:

```
./fidespipebot.exe report -run var/bot/runs/<order>/<run> -kind username -target wykserdex -out var/bot/reports/x
```

`-kind` — `username` или `email`.

## Что проверено, а что нет

Проверено на реальных прогонах:

- бесплатный скан ника: 19 сайтов, 6 профилей;
- платный скан ника: 420 сайтов, 13 профилей, 85 с на оба источника;
- платный скан адреса: синтаксис + MX + 122 сайта holehe;
- отчёт: `report.html` без следов шаблона, `evidence.json` и `journal.jsonl`
  с тем же `run_id`, что в подписи отчёта;
- вход: `/check` не принимает ничего, кроме ника из 3–32 `[A-Za-z0-9_]` и
  адреса — строка вида `--input=x` не разворачивается флагом в CLI движка;
- `go test ./internal/bot` — 7 тестов; восьмой (донорский E2E про `PATH`)
  пропускается без `FIDESPIPE_BOT_E2E=1`, потому что требует сети и доноров.

Не проверено без токенов (и проверить может только первый запуск):

- реальный `getUpdates`/`sendMessage`/`sendDocument` — код пишется по описанию
  Bot API, но ни один запрос не уходил в Telegram;
- реальный `createInvoice` и зачисление USDT;
- поведение под параллельными заказами клиента (полупродуктивно: тесты гоняют
  один заказ).

Первые 2–3 заказа стоит проводить руками, глядя в лог.

## Как устроено честно

- Бесплатный текст содержит только счётчики: ссылки — платная часть.
- Проваленный источник помечается в отчёте проваленным с причиной из журнала.
  «Ноль находок» и «источник не ответил» — разные заявления покупателю, и
  движок их не путает: `context.json` знает только дошедшие шаги, поэтому
  список источников берётся из `journal.jsonl`.
- Число проверенных сайтов складывается только там, где `checked` действительно
  означает объём проверки. У `maigret` simple-отчёт содержит только находки, и
  его `checked` в сумму не попадает — иначе счётчик в шапке был бы выдуманным.
- `report.html` собирается через `html/template`, сообщения в Telegram —
  только обычным текстом: в них попадают чужие ники и вывод плагинов.
- Движок для продукта не изменялся: бот вызывает `fidespipe pipeline run`
  как внешний процесс, поэтому песочница, журнал и доверие по sha256 работают
  ровно как в CLI.
