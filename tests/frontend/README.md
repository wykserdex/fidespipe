# Фронтенд-стенды редактора и режима артефактов

Четыре независимые вещи, которые нечем проверить `go test`: логика браузерного
JS и то, как страница выглядит на самом деле.

| файл | что проверяет | запуск |
|---|---|---|
| `drag_harness.js` | связывание жестом в редакторе: протяжка выхода в поле входа, дроп по наведению без выбора пары, отмена | `node tests/frontend/drag_harness.js` |
| `chain_harness.js` | сборщик цепочки: переносит ли сценарий в документ свои поля (ключи, гейты, цикл) и **не** переносит ли сеть, с предупреждением вместо молчаливого deny | `node tests/frontend/chain_harness.js` |
| `artifacts_harness.js` | режим артефактов: загрузка, планирование связей, генерация YAML | `node tests/frontend/artifacts_harness.js . http://127.0.0.1:8765` |
| `cdp.js` | браузер под управлением: скриншоты и настоящие клики | `node tests/frontend/cdp.js <url> <out.png> [actions.json]` |

Первые три исполняют **настоящие функции** из `web/static/editor/app.js` и
`web/static/artifacts/app.js` против замоканного DOM. Не копии логики: если
сломать `dropLink`, сломается и стенд.

## Почему нужен ещё и chain_harness

`openFile` (открыть файл) и `applyPreset` (собрать цепочку из сценария) — два
разных пути в `state.doc`, и потеря поля выглядит по-разному. Первый закрыт
Go-тестом `TestEditorRoundTripPresetsNoFieldLoss` (все пресеты реестра через
parse → serialize → parse). Второй — чистый JS, и его не видели оба теста:
сборщик не переносил `network` и `secrets`, а пайплайн всё равно сохранялся
(кросс-чек ключей живёт в предупреждениях) и падал уже на запуске с
`secrets_missing`. Отсюда правило: **новый путь в `state.doc` — новая строка
в этом стенде.**

## Сеть и ключи в сборщике — не «поля файла», а разные вещи

`secrets` переносятся, `network` — нет, и стендер держит эту разницу отдельно:

- **ключ — объявление.** `secrets: [KEY]` говорит «читай KEY из окружения», сам
  ключ остаётся у человека. Раннер требует наличия КАЖДОГО объявленного ключа,
  поэтому потеря объявления = потеря данных о цепочке (ран падает с
  `secrets_missing`).
- **сеть — доступ.** Собирать цепочку из пресета с `network: allow` и получить
  готовый доступ в сеть одним кликом нельзя: сеть выдаёт человек. Собранная
  цепочка остаётся без сети (пустое поле = deny), ядро отвечает на это
  `E_NETWORK_DENIED` с формулировкой «поле network не задано…», и в панели ошибок
  появляется кликабельная кнопка «разрешить сеть». Молчаливый deny недопустим,
  поэтому стендер требует, чтобы подпись на холсте прямо говорила: сеть из
  сценария **не перенесена**, выдать её нужно кликом.

## Почему это не ловится Go-тестами

`web/static` — встроенный JS без модулей и без сборки; `go test` до него не
дотягивается. Стенды закрывают ровно тот класс ошибок, что Go не видит:

* `renderPicker` передавал в `suggest()` запись шага вместо объекта плагина —
  подсказки молча выходили пустыми **в живом интерфейсе**, при этом стенд
  проходил, потому что кормил `suggest()` настоящим плагином;
* `build()` считал `errors || issues`, а эндпоинт отдаёт `errors: null`,
  когда ошибок нет, — предупреждения объявлялись ошибками;
* валидный YAML с экранированием не собирался: путь с кавычкой ломал разбор.

## artifacts_harness ходит в живое ядро

Сгенерированный YAML отправляется на `POST /api/validate/pipeline`, и
проверяется `ok`, а не совпадение строк с ожиданием. Отдельная проверка
убеждается, что ядро **отвергает** несуществующий плагин: иначе проверка
«ядро приняло» ничего бы не значила.

Требуется запущенный GUI без сессии:

    go build -o fidespipe.exe ./cmd/fidespipe
    ./fidespipe.exe gui --listen 127.0.0.1:8765 --no-session

Фикстуры плагинов берутся из `/api/plugins`, а не пишутся руками: рукописные
данные дважды соврали с реальными манифестами и стенд «находил» несуществующие
проблемы.

## cdp.js — зачем он

Node 26 даёт глобальный `WebSocket`, поэтому Chrome поднимается с
`--remote-debugging-port` и с ним можно говорить по CDP без зависимостей.
Это единственный способ увидеть страницу глазами и потыкать её настоящими
событиями мыши. Так были найдены ошибки, которых не видели стенды: пустая
страница артефактов без сессии, наложение двух узлов в редакторе, подписи,
уехавшие в левую колонку.

    node tests/frontend/cdp.js http://127.0.0.1:8765/artifacts/ out.png actions.json

`actions.json` — список действий: `{"wait":500}`, `{"click":[x,y]}`,
`{"drag":[x1,y1,x2,y2]}`, `{"eval":"js"}`, `{"shot":"other.png"}`.

Требуется Chrome или Edge; путь ищется автоматически. Скриншоты и клики
использовались только для проверки своего же кода.

## Чего стенды не проверяют

Внешний код и песочница. Плагин без записи в allow-list доверия на Windows не
запустится вовсе (изолятора нет), и стенд этого не заметит — это политика
ядра, а не логика интерфейса.
