# dirsearch

Брутфорс директорий и файлов веб-сервера (maurosoria/dirsearch), обёртка над CLI.
Отчёт `dirsearch -o <file> --output-formats json` разбирается в плоский список path/status/size; рекурсия (`-r`) не включается.

## Установка донора

Пин объявлен в манифесте (`runtime.requires: ["dirsearch==0.5.0"]`) и в
`requirements.lock`, поэтому ставится вместе с плагином:

```
pip install dirsearch==0.5.0
```

Путь к бинарю переопределяется env `DIRSEARCH_BIN`.

## Тесты

`fidespipe plugin test plugins/community/dirsearch` — 15 кейсов, и они разделены
намеренно:

- **реальный инструмент** (два кейса с `{{base_url}}`) сканирует локальный
  сервис, который поднимает сам раннер: `services: [{type: http, root:
  fixtures/site}]` отдаёт каталог фикстур на свободном порту `127.0.0.1`, а
  `{{base_url}}` подставляется во вход кейса. Проверяется то, чего мок не может:
  что донор реально ходит по сети, что его отчёт совпадает с содержимым фикстуры
  (`/admin` → 301, `/secret.txt` → 200 и 16 байт) и что пустой результат —
  честный «ничего не нашлось». Пока dirsearch не установлен, эти кейсы падают с
  `dirsearch_not_installed`: это правда, а не сбой теста;
- **мок** (`mock_dirsearch.py`) проверяет ветки отказа: пустые и неверные входы,
  ненайденный словарь, таймаут, отсутствующий бинарь, битый отчёт, «упал».
  Настоящий dirsearch нельзя детерминированно заставить упасть на конкретном
  входе.

Значения в фикстурах выдуманы, слово `topsecret` — не настоящий секрет.
Точные размеры в ожиданиях зависят от содержимого фикстур и от версии донора
(в CI пин `dirsearch==0.5.0`).

Осторожно с `wordlist`: относительный путь проверяется от каталога плагина, а
dirsearch поедет с `cwd` во временной папке — поэтому обёртка передаёт донору
абсолютный путь. Без этого живой кейс падал бы с «words.txt does not exist».
