# pyelftools

Разбор ELF-файлов: класс (ELF32/ELF64), тип объекта и машина по словарям
донора, таблица секций и список подключаемых библиотек DT_NEEDED.

## Установка донора

Пин объявлен в манифесте (`runtime.requires: ["pyelftools==0.33"]`) и в
`requirements.lock`:

```
pip install pyelftools==0.33
```

У pyelftools **нет ни CLI, ни консольного скрипта** — проверено: у пакета 0.33
нет ни одного entry point. Поэтому плагин работает паттерном C: запускает тот
же интерпретатор с фиксированным сниппетом (`-c`), который импортирует
`elftools` и печатает один JSON в stdout. Искать бинарь в PATH было бы поиском
того, чего нет. Сниппет можно подменить env `PYELFTOOLS_BIN` (имя из PATH,
полный путь или `.py`-мок).

## Порты

| порт | тип | источник |
|---|---|---|
| `file` | string, file_ref | путь к ELF-файлу; на выходе — строка оператора, не абсолютный путь |
| `elf_class` | string | `ELF64` / `ELF32` |
| `elf_type` | string | `ET_DYN` / `ET_REL` / `ET_EXEC` / `ET_CORE` |
| `machine` | string | `EM_X86_64` / `EM_386` / … |
| `entry` | number | `e_entry` |
| `sections` | array | `{name, type, flags, size, addr}` |
| `libraries` | array | `DT_NEEDED` по порядку тегов `.dynamic` |
| `section_count` | number | сколько секций |
| `parser_version` | string | `elftools.__version__` — собственный атрибут донора |

`type` секции и `machine` приходят **из словарей донора** (`SHT_PROGBITS`,
`EM_X86_64`). Своей таблицы у обёртки нет: у pyelftools её нет и быть не может,
а вторая правда устарела бы первой. Пустая строка означала бы «эта версия не
знает такой код».

### `flags` — число, а не «A/W/X»

`SH_FLAGS` у pyelftools — это набор констант, а не карта «бит → имя».
Разложить `sh_flags` в буквы значило бы завести таблицу в обёртке, то есть
ровно ту вторую правду, которой здесь нет. Поэтому наружу уходит число из
файла, а не расшифровка.

### Чего в выводе нет

- **Символы** (`.symtab`/`.dynsym`) не собираются вообще. Имя символа типа
  `STT_FILE` — это путь к исходнику на машине сборки, то есть внутренний
  идентификатор сборки.
- **`.note.gnu.build-id`** не читается: это хеш-отпечаток файла (то же, что
  imphash в PE) — по нему образ опознаётся без содержимого.
- **Абсолютный путь**: наружу уходит строка `file` ровно та, что дал оператор.

## Фикстуры

`fixtures/` собраны скриптом `fixtures/make_elf.py`:

```
python fixtures/make_elf.py
```

На Windows нет кросс-тулчейна, который собрал бы Linux-бинарник (mingw даёт PE),
а файл «просто с магией ELF» был бы подделкой, поэтому ELF собирается побайтно
по спецификации System V ABI. Чем проверялось, что фикстуры настоящие:

- `readelf -h -l -d -S` (binutils из mingw-w64) — разбирает без ошибок;
- `pyelftools 0.33` — читает все секции и оба тега `DT_NEEDED`;
- `LIEF 1.0.0` — видит формат ELF, секции и зависимости.

| файл | что это | что проверяет |
|---|---|---|
| `libfixture.so` | ELF64, ET_DYN, EM_X86_64, 8 секций, DT_NEEDED libc.so.6 и libpthread.so.0 | основной разбор, DT_NEEDED, словари донора |
| `fixture32.o` | ELF32, ET_REL, EM_386, 3 секции, без DT_NEEDED | другой класс и другой тип: поля приходят от донора |
| `truncated.so` | первые 60% `libfixture.so` | `ELFParseError` → `bad_file`, а не `not_elf` |

Динамический ELF нужен именно потому, что у статического бинарника нет секции
`.dynamic`, и порт `libraries` было бы нечем проверять.

Файлы детерминированы: ни времени сборки, ни случайных байт, ни имён
пользователя в них нет.

## Тесты

`fidespipe plugin test plugins/community/pyelftools` — 23 кейса, и они разделены
намеренно:

- **реальный инструмент** (кейсы без `PYELFTOOLS_BIN`) запускают настоящий
  pyelftools на фикстурах из `fixtures/` и сверяют точный состав таблицы
  секций (вместе с порядком), DT_NEEDED, класс, тип, машину и версию донора;
  отдельно — что `.bss` даёт `size: 64` (размер в памяти, а не на диске) и
  что обрезанный файл отличен от не-ELF. Пока донор не установлен, эти кейсы
  падают — это правда, а не сбой теста;
- **мок** (`mock_pyelftools.py`) проверяет ветки отказа: `not_elf`, `bad_file`,
  не импортируется, таймаут, пустой stdout, битый JSON и ответ без версии.
  Настоящий донор нельзя детерминированно заставить вернуть битый JSON.

Фикстуры передаются относительными путями: подпроцесс плагина стартует в
каталоге плагина, абсолютный путь в тесте был бы привязан к машине.

## Сеть

`permissions.network: []` — и это правда: разбор локальных байтов. Проверено
запуском с заблокированными `socket.connect`, `connect_ex`,
`create_connection`, `getaddrinfo` и `gethostbyname`: тот же exit 0, тот же
разбор и **ноль** попыток соединения.
