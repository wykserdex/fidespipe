# msoffcrypto_tool

Проверка и расшифровка офисных документов, закрытых паролем
(nolze/msoffcrypto-tool): зашифрован ли документ, каким шифрованием, и — если
задан `out` — расшифровка в открытый текст.

## Установка донора

Пин объявлен в манифесте (`runtime.requires`) и в `requirements.lock`:

```
pip install msoffcrypto-tool==6.0.0
```

По умолчанию плагин запускает `python3 -c <сниппет>` с тем же интерпретатором,
а не console-script `msoffcrypto-tool`: pip кладёт скрипты в каталог `Scripts`
(на Windows), а он часто не в PATH — и донор оказывается установленным и «не
найденным» одновременно. Путь к донору можно переопределить env
`MSOFFCRYPTO_TOOL_BIN` (имя из PATH, полный путь или `.py`-мок).

## Пароль

Пароль читается **только** из env `MSOFFCRYPTO_PASSWORD`. Во входе его нет (вход
рана уходит в контекст и в журнал), и в argv он не попадает никогда: единственный
способ CLI `msoffcrypto-tool` принять пароль — флаг `-p`, а argv виден в списке
процессов любому пользователю машины. Поэтому пароль уходит в **stdin** донора.

Без пароля в env плагин ничего не расшифровывает — только проверяет документ.

## Куда пишется расшифрованный файл

`out` — единственный порт, который решает, будет ли вообще расшифровка:

- абсолютный путь — пишем туда, как сказали;
- относительное имя — кладём во временный каталог ОС, а **не** рядом с
  `main.py`. Запись внутри каталога плагина меняет хэш его содержимого, и
  следующий запуск получил бы отказ «не в allow-list доверия ядра» — вплоть до
  красных `fidespipe plugin test` на этом же плагине;
- `out` не задан — расшифровки не происходит (`decrypted: false`).

Путь результата наружу **не отдаётся**: абсолютный путь — это внутренний
идентификатор машины, и по нему в контекст рана попадёт путь хоста. Каталог с
результатом намеренно не убирается.

## Порты

| порт | тип | источник |
|---|---|---|
| `file` | string | строка оператора; абсолютная форма ничего не добавила бы |
| `encrypted` | boolean | `OfficeFile.is_encrypted()` донора |
| `encryption_type` | string | `type` донора: `agile`, `standard`, `extensible`, `plain` (OOXML), `xor`, `rc4`, `rc4_cryptoapi` (xls/doc/ppt) |
| `decrypted` | boolean | расшифровано ли в этом запуске |
| `decrypted_size` | number | размер открытого текста, который донор записал; 0 без расшифровки |
| `tool_version` | string | версия пакета `msoffcrypto-tool` из метаданных |

Пустой `encryption_type` означает «эта версия донора не назвала тип», а
`tool_version` обязателен: без него «документ не зашифрован» неотличимо от «эта
версия не знает такой тип шифрования».

## Чего в выводе нет и почему

- `office.info` — соль, `encryptedVerifierHashValue`, `encryptedKeyValue`,
  `keyDataSalt`, `encryptedHmacValue`: проверочные хеши пароля и ключевой
  материал. Для слабого пароля они перебираются офлайн, поэтому наружу не
  отдаётся ничего из `info`. Поля копируются по списку разрешённых имён, а не
  «всё, кроме известного»: новое поле донора не должно само собой утекать в
  вывод плагина.
- `office.secret_key` — производная от пароля, тот же случай.
- сам пароль — ни в выводе, ни в тексте ошибок.

## Фикстуры

`fixtures/` собраны `fixtures/make_office.py`: `plain.docx` — настоящий
незашифрованный OOXML-пакет (собирается байт-в-байт повторяемо, zip с
фиксированным mtime), `encrypted.docx` — он же, зашифрованный **самим
донором** паролем `Fixture-Passw0rd` (пароль — часть фикстуры, а не секрет:
он написан открытым текстом в сборщике, в тестах и здесь).

`plain.docx` специально больше 4096 байт: у msoffcrypto-tool 6.0.0
`ECMA376Agile` делит открытый текст на сегменты по 4096 байт, и при одном
сегменте `encrypt()` даёт файл, который сам же `decrypt()` расшифровать не
может (проверено на пакетах 403, 803, 1303, 1384, 1391 и 2303 байта — все
четыре: `InvalidKeyError` либо «длина не кратна длине блока»; начиная с 4399
байт round-trip сходится). Настоящие `.docx` больше 4 КБ всегда.

`encrypted.docx` байт-в-байт не повторяется — при шифровании соль и `spinCount`
выбираются случайно (проверено: два прогона подряд дают разные файлы). Повторяемо
то, что проверяют тесты: после расшифровки получается байт-в-байт исходный
`plain.docx`, а разобранные значения донора от соли не зависят.

Плагин для аудита собственных или явно полученных для проверки документов.
