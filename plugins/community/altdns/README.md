# altdns

Генерация перестановок поддоменов по словарю (infosec-au/altdns): из известного
субдомена строятся кандидаты вида `dev-www`, `dev.www`, `www-dev` для
последующего брутфорса. DNS-запросов плагин не делает.

## Установка донора

Пины объявлены в манифесте (`runtime.requires`) и в `requirements.lock`:

```
pip install py-altdns==1.0.2 tldextract==4.0.0
```

Два пина, а не один. `py-altdns` 1.0.2 делает `from tldextract.tldextract
import LOG` на верхнем уровне, а в `tldextract` 5.0 символ `LOG` удалён: с
`tldextract` 5.4.0 (то, что резолвит pip сегодня) донор падает на `ImportError`
ещё до разбора аргументов — `exit 1`, traceback, ни одного перестановочного
имени. `tldextract==4.0.0` — последняя версия, где `LOG` есть.

По умолчанию вызывается `python3 -m altdns`, а не console-script `altdns`: pip
кладёт скрипты в каталог `Scripts` (на Windows), а он часто не в PATH — и донор
оказывается установленным и «не найденным» одновременно. Путь к бинарю можно
переопределить env `ALTDNS_BIN` (имя из PATH или полный путь).

## Порты

| порт | тип | источник |
|---|---|---|
| `host` | string, text | известный субдомен, из которого строятся перестановки |
| `words` | array, optional | слова для подстановки; без него — дефолт обёртки |
| `number_suffix` | boolean, optional | ещё и варианты `sub-0..sub-9` (флаг `-n` донора) |
| `permutations` | array | строки перестановки в терминах донора («altered subdomain») |
| `total` | number | сколько перестановок |
| `generator_version` | string | версия пакета `py-altdns` из `importlib.metadata` |

Порта `threads` нет намеренно: `-t` у донора ограничивает резолвер, а резолвер
(`-r`/`-s`) обёртка не запускает никогда. Порт «чтобы задать потоки» был бы
обещанием, на которое в этом коде нечем ответить.

`permutations` — плоский список имён, какой отдаёт донор. Порядок задаёт
обёртка: донор дедуплицирует через `set()` и печатает в порядке обхода
множества, который от прогона к прогону меняется, поэтому выход сортируется.

### Чего в выводе нет

Абсолютный путь временного каталога, который донор пишет в stderr
(`[*] Wrote 12 altered subdomains to …`), в stderr плагина не попадает: он
заменяется на `<tmp>`. Иначе журнал рана был бы привязан к машине. Остального
у altdns нет — ни хешей, ни идентификаторов.

### Про `generator_version`

У altdns нет ни флага `--version`, ни атрибута `__version__` — печатать нечего.
Версия берётся из метаданных установленного пакета (тот же источник, что у
`pip`), потому что перестановки зависят и от версии донора, и от снимка public
suffix list внутри `tldextract`. Если метаданных нет, а донор как-то запустился
(например, модуль подложен в `PYTHONPATH`), плагин **не** отдаёт результат:
перестановки были бы приписаны версии, которой нет.

## Сеть

`permissions.network` — 443, и это не формальность. Замер: внутри `altdns`
используется `tldextract`, который при первом обращении тянет список public
suffix с `publicsuffix.org`; с заблокированными `socket.connect` вызов донора
доходит до попытки соединения именно туда.

При недоступной сети `tldextract` откатывается на встроенный снимок списка —
замер: тот же вход и те же 12 перестановок при соединениях, падающих с
`OSError`. Поэтому тесты офлайн и детерминированы.

Резолв (`-r`, `-s`) в командной строке не включается **никогда**: DNS-запросов
донор не делает.

## Словарь по умолчанию

Ключ `-w` у донора обязателен, своего словаря у него нет. Перечень из восьми
слов (`admin, api, beta, demo, dev, qa, stage, test`) — политика обёртки, а не
донора; он зафиксирован тестом, чтобы «сменился дефолт» было видно красным
прогоном. Для работы с другим словарём передавайте `words`.

## Тесты

`fidespipe plugin test plugins/community/altdns` — 19 кейсов, и они разделены
намеренно:

- **реальный инструмент** (кейсы без `ALTDNS_BIN`) запускают настоящий
  `python3 -m altdns` и сверяют вывод с тем, что донор отдаёт на этих входах:
  12 перестановок для `www.example.com` со словарём `[dev, test]`, 6 для
  `[dev]`, 26 с `-n`, 48 на дефолтном словаре и **одна** для `example.com`
  (у хоста без субдоменной метки результат непустой — видно только на живом
  доноре, потому что делит домен `tldextract`). Пока донор не установлен, эти
  кейсы падают — это правда, а не сбой теста;
- **мок** (`mock_altdns.py`) проверяет ветки отказа: упавший донор, отсутствие
  `No module named` → «не установлен», нет файла `-o`, битый отчёт, таймаут.
  Настоящий бинарь нельзя детерминированно заставить упасть на конкретном
  входе.

Фикстуры-файлы не нужны: файлового входа у плагина нет. Фикстура здесь — сам
вектор входа (`host` + `words`), и группа реальных кейсов сверяет его с живым
выводом донора, а не с фикстурой автора теста.
