# detect_secrets

Поиск секретов в коде и конфигах (Yelp/detect-secrets): тип находки, путь и
номер строки. Значения секретов и их SHA-1 наружу не отдаются — только места.

## Установка донора

Пин объявлен в манифесте (`runtime.requires: ["detect-secrets==1.5.0"]`) и в
`requirements.lock`, поэтому ставится вместе с плагином:

```
pip install detect-secrets==1.5.0
```

По умолчанию вызывается `python3 -m detect_secrets`, а не console-script
`detect-secrets`: pip кладёт скрипты в каталог `Scripts` (на Windows), а он
часто не в PATH — и донор оказывается установленным и «не найденным» одновременно.
Путь к бинарю можно переопределить env `DETECT_SECRETS_BIN` (имя из PATH или
полный путь).

## Порты

| порт | тип | источник |
|---|---|---|
| `path` | string, file_ref | файл или каталог для сканирования; на выходе `path` — абсолютная форма того, что реально просканировано |
| `wall_timeout` | number, optional | общий лимит рана, секунды (по умолчанию 300) |
| `secrets` | array | находки `{type, filename, line_number}` |
| `count` | number | сколько находок |
| `detector_version` | string | версия набора детекторов донора |

`filename` — путь **относительно корня сканирования** (того каталога, который
передан в `path`), всегда со слэшем независимо от ОС. `type` — символическое
имя от донора дословно (`Secret Keyword`, `AWS Access Key`), свой словарь типов
обёртка не заводит.

Наружу не отдаются: `hashed_secret` (SHA-1 от значения секрета — для пароля
низкой энтропии восстанавливается перебором), `is_verified` (появляется только
после сетевой проверки), `generated_at`, `plugins_used`, `filters_used`.

## Сеть

`permissions.network: []` — и это правда: сканирование запускается при
заблокированных `socket.connect` / `create_connection` / `getaddrinfo` и даёт
тот же exit 0 и те же находки. У донора сетевые пути есть (`verify` / `audit`),
но обёртка их не включает: в командной строке только
`scan <путь> --all-files`.

## Тесты

`fidespipe plugin test plugins/community/detect_secrets` — 16 кейсов, и они
разделены намеренно:

- **реальный инструмент** (кейсы без `DETECT_SECRETS_BIN`) запускают настоящий
  `detect_secrets` по фикстурам из `fixtures/` и проверяют контракт: типы портов,
  имена полей, номера строк, порядок. Пока донор не установлен, эти кейсы
  падают — это правда, а не сбой теста;
- **мок** (`mock_detect_secrets.py`) проверяет ветки отказа: упавший донор,
  битый baseline, baseline без `version`, таймаут, отсутствующий бинарь.
  Настоящий бинарь нельзя детерминированно заставить упасть на конкретном входе.

Фикстуры отдаются относительными путями: подпроцесс плагина стартует в каталоге
плагина, абсолютный путь в тесте был бы привязан к машине. Значения в фикстурах
выдуманы; ключ AWS — опубликованный пример из документации AWS.
