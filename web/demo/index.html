An orchestrator for
other people’s tools.

Fidespipe runs plugins written by strangers behind a declared contract, journals every step to disk, and stops for a human when the verdict is the point.

The demo below is not a simulation and not a re-implementation. It is the shipped Go engine compiled to WebAssembly, running in this tab: the same core.Validate and core.Run the CLI calls, writing a real journal.jsonl to a real filesystem.

    What it actually is
    
  
    
    The tools are other people’s. They are written and patched by people who will
    never meet each other. Fidespipe does not try to make them agree — it puts a
    boundary between them and keeps a record of what crossed it.
  
    
  
    
    
      
    
        Contract at the boundary
        Every plugin declares typed input and output ports. They are checked
        before the run, so a broken chain fails at validation instead of
        halfway through step four. Try the broken preset above.
      
    
      
    
        Run journal
        Each run is a directory on disk: journal.jsonl, a context
        snapshot, artifacts. A killed run can be resumed from where it stopped rather
        than silently restarted.
      
    
      
    
        Human in the loop
        core/human_gate parks the run and waits for an actual
        decision, with a wait ceiling and approval via signed link from any device.
        --yes exists for CI; it never applies to a gate marked
        approval: human.
      
    
      
    
        Trust by hash
        Plugins are addressed as id@sha256:…. Edit the file and the
        trust is gone. A plugin’s name is not evidence of anything.
      
    
      
    
        Isolation
        Untrusted code goes into a sandbox: bubblewrap on Linux, AppContainer on
        Windows. The plugin directory is mounted read-only and the network is denied
        unless a capability says otherwise.
      
    
      
    
        Supply chain
        Releases carry an SPDX SBOM and SHA256SUMS, both signed with sigstore.
        Donor packages are pinned and hash-checked.
      
    
      
    
        Three ways in
        The same pipelines and the same gate are reachable from the terminal, from
        a browser console, and over MCP (8 tools, exec_plugin off by
        default). An agent is a client, not the product.
      
    
        
  
    

    


    
  
    What this page cannot show
    
  
      
    
    • 
      Only builtin plugins run here. The registry holds 100 plugins;
      98 of them are Python subprocesses, and a browser cannot start a process. This
      demo runs core/text_stats and core/human_gate, which
      execute in-process. Everything else needs the real binary.
    
      • 
    
    • 
      No sandbox to demonstrate. Isolation is the reason the
      untrusted plugins are safe to run at all, and bubblewrap and AppContainer do not
      exist in a tab. The demo has nothing to isolate.
    
      • 
    
    • 
      The filesystem is in memory. journal.jsonl is real
      and is written by the real journal.Journal, but it lands in a
      Node-fs-shaped shim over a JS Map, so it disappears on reload.
    
      • 
    
    • 
      Version 0.x, honestly. The protocol is versioned and there is a
      compatibility document, but the API is not frozen and the author says so.
    
      • 
  
    
  
    
    To see the rest, build it — it needs Go 1.26+ and nothing else for the demo
    path:
  
    
  
    go build -o fidespipe ./cmd/fidespipe
./fidespipe demo          # no git, no Python, no network
./fidespipe doctor        # what is missing in your environment
./fidespipe plugin list   # all 100
