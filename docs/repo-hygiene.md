# Что не место в публичном репозитории и как это убрать

Разбор от 2026-10-02. Речь не про качество кода — с ним как раз всё в порядке —
а про то, что публичный репозиторий читают как витрину, и сейчас витрина
показывает внутреннюю переписку.

## Что вынесено из дерева (в этой ветке)

Файлы сняты с трекинга (`git rm --cached`), на диске остались и добавлены в
`.gitignore` — рабочий процесс не меняется, агент по-прежнему читает `AGENTS.md`
локально.

| Файл | Почему не публикуется |
|---|---|
| `AGENTS.md` | инструкция для агента: путь Telegram-канала, локальная VM с логином и паролем, «текущая задача» |
| `OUTREACH_ROUND2.md` | план холодных рассылок, копипаст-письма, описания конкретных людей |
| `OUTREACH_TRACKER.md` | таблица «кого спросили / кто ответил» |
| `archive/POSTS.md` | черновики постов + чек-лист, где пункт 1 — «отозвать утёкший GitHub token» |
| `archive/M5_FEEDBACK.md` | 58 КБ разбора фидбека внешних тестеров |
| `archive/LANDING.md`, `archive/TESTER_PACKET_5.md` | материалы той же волны |
| `attic/*.archived` | некомпилируемый код macOS-бэкенда: не собирается, не тестируется, а `SECURITY.md` ссылался на него как на «сохранённый» |

Ссылки на вынесенное поправлены, а не оставлены битыми: `SECURITY.md`,
`README.en.md`, `docs/architecture.md`, `docs/versioning.md` и комментарии в
`internal/plugin/sandbox*.go` теперь называют коммит `9d17120` — провенанс
решения сохранён, дерево не засорено.

## Что делать с историей

Из текущего дерева файлы убраны, но в истории коммитов они остались — а именно
историю читают первым делом. Пока это не сделано, шаг выше решает половину
задачи: для нового читателя клона — да, для grep по истории — нет.

```bash
# 1. Свежая копия и backup-ветка: перезапись истории необратима
git clone https://github.com/wykserdex/fidespipe fidespipe-purge && cd fidespipe-purge
git branch backup-before-purge

# 2. Вырезать пути из ВСЕХ коммитов (не только из HEAD)
git filter-repo \
  --path AGENTS.md \
  --path OUTREACH_ROUND2.md \
  --path OUTREACH_TRACKER.md \
  --path archive/ \
  --path attic/ \
  --invert-paths

# 3. Проверить, что не осталось следов
git log --all --oneline -- AGENTS.md archive/ attic/   # пусто
git log --all -p | grep -inE 'ghp_|sk-[A-Za-z0-9]{20,}|password' | head

# 4. Опубликовать: force-push + перенос тегов (теги — это те же коммиты)
git remote add origin https://github.com/wykserdex/fidespipe
git push --force --all
git push --force --tags

# 5. Соседние клоны/форки после перезаписи несовместимы: их надо переклонировать
```

Требуется `git filter-repo` (`pip install git-filter-repo`).

**Если перезапись истории сейчас не хочется** — есть дешёвый вариант без
force-push: сделать репозиторий архивным/приватным и опубликовать чистый, с
историей от текущего состояния. Дороже по звёздам, дешевле по риску.

## Отдельно: токен

`archive/POSTS.md` (теперь вынесенный) фиксирует, что GitHub-токен
`ghp_...` был написан в чате и использован для push. В истории коммитов токена
нет — проверено `git log --all -p` по типовым паттернам. Но если он не отозван
до сих пор: отозвать в настройках GitHub (Settings → Developer settings →
Personal access tokens) — это занимает минуту и не зависит от чистки истории.

## Проверки, чтобы это не вернулось

CI уже проверяет, что в `var/runs` не просачиваются журналы
(`test -z "$(git ls-files var/runs)"`). Туда же по смыслу просится проверка
«внутреннее — не в дереве»:

```yaml
- name: internal notes stay out of the public tree
  run: |
    set -eu
    for p in AGENTS.md OUTREACH_TRACKER.md OUTREACH_ROUND2.md archive attic; do
      if git ls-files --error-unmatch "$p" >/dev/null 2>&1; then
        echo "внутренний путь $p попал в индекс: ему здесь не место" >&2
        exit 1
      fi
    done
```

И правило на будущее: внутренние заметки живут в отдельном приватном
репозитории или в вики, а не в `main` публичного.
